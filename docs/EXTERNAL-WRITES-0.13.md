# External disk writing — Harbour OS 0.13.0

Connected disks still open read-only. In **Files → Connected disks**, open a supported volume, choose **Enable writing**, acknowledge the change, and type `WRITE serial` (the UUID or volume identifier is used when no serial is available). The disk's identity, mounted source, mount mode and OS/pool/active-array protection are checked again. Nothing is formatted. Installing this update never enables writing on a physical disk.

Writable formats: NTFS (ntfs-3g), exFAT, FAT/FAT32, ext2/3/4, Btrfs, XFS and F2FS. APFS, HFS/HFS+, ISO9660 and UDF remain read-only in this interface. Encrypted volumes, ZFS pools and multi-device imports remain separate workflows. No `force`, `remove_hiberfile`, journal repair or filesystem conversion is performed. NTFS write mounts use `norecover` and may be refused for dirty or hibernated Windows disks.

Once enabled, the external browser offers uploads with byte progress/cancellation, new folders, rename and permanent deletion. Existing names cannot be overwritten. FAT32 uploads must be smaller than 4 GiB. Uploads use a temporary file and publish only after the declared data has arrived and been flushed. An interrupted request removes its temporary file; completed files remain if a later upload in the selection fails or is cancelled. New files and folders on Linux POSIX filesystems use the Harbour owner's UID/GID. Existing ownership is preserved by renames.

Deletion requires `DELETE item-name` and permanently removes the selected file or folder, including nested contents. It does not use the data pool's recycle bin. Symlinks are not followed for file changes; directory descriptors keep operations confined to the verified external mount. Uploads, mutations and mount changes are serialized. App/API authentication and CSRF protections restrict these controls to the owner.

**Make read-only** cleanly unmounts and reopens the volume read-only. **Eject** unmounts it normally, flushing the filesystem; no forced/lazy unmount is used. A failed write mount attempts to reopen read-only. A web-service restart retains a verified live mount; a host reboot does not automatically remount an external disk or enable writing. Eject writable external disks before rolling back to older Harbour versions that only understand read-only mounts.

Validation: 167 regression tests, JavaScript syntax checks, and real disposable-loop-image acceptance for all nine writable formats. The acceptance verifies uploads, persistent bytes across remounts, Linux ownership, file/folder rename collisions, interrupted-upload cleanup, symlink confinement, typed deletion, and restoration to read-only. The same acceptance runs in BIOS and UEFI ISO boot tests. Physical data disks are not used as test fixtures.
